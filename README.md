# 《来电疑云》

**七牛云 Builder Day · 灵矽赛题「语音类游戏（非跑团）」落地作品**

> 一句话定位：基于灵矽多人语音通道的**辨谎推理互动内容**——系统播报混有真假信息的可疑来电，玩家通过盘问、物证研判、怀疑标记与投票，找出隐藏的「来电骗子」，并在对局中提升真实场景下的风险判断力。

| 维度 | 落点 |
| --- | --- |
| 赛题：语音类游戏 | 全流程以主持播报 + 玩家口头发言为主，键盘仅为降级通道 |
| 赛题：非跑团 | 无 DM、无自由叙事；阶段 / 身份 / 胜负由服务端状态机权威裁定 |
| 形态：类狼人杀 | 隐藏身份 + 发言博弈 + 投票出局；主题收敛为「识破诈骗来电」 |

**好玩是入口，防骗是结果。**

## 快速开始

```bash
make tidy
make run
```

启用灵矽同款 CosyVoice 音色（推荐）：

```bash
export DASHSCOPE_API_KEY=sk-你的百炼密钥
# 可选：COSYVOICE_MODEL=cosyvoice-v2
make run
```

浏览器打开 [http://127.0.0.1:8080](http://127.0.0.1:8080)

- **单人演示**：点「单人演示（补机器人）」→「开始游戏」→ 按阶段操作  
- **多人**：一人创建房间，其他人输入房间号加入（建议 3–6 人）  
- **语音输入**：按住说话 → 本地 Whisper；也可打字（首次请 `make asr-deps`，需 [ffmpeg](https://ffmpeg.org/)）  
- **音色**（已配置密钥）：主持 `longxian_v2`；玩家轮换 `longze_v2` / `kabuleshen_v2` / `longcheng_v2`；未配置则回退浏览器 TTS  

无界面跑通一局：

```bash
make demo
```

本地灵矽代码参考：`xrobotd`（对齐 `qbox/xrobotd` `v0`）。

## 产品设计

### 设计目标

1. **可听懂**：主持词 `hostLine` 驱动全场节奏，闭眼也能跟局  
2. **可说清**：发言以短口语为主，适配 ASR 与设备麦克风  
3. **可裁定**：身份、阶段、技能、投票由服务端权威状态机保证公平  
4. **可扩展**：剧本与通道解耦；同一引擎可换行业剧本、换接入端  

### 角色与信息分层

| 角色 | 私密信息 | 公开行为 |
| --- | --- | --- |
| 市民 | 可靠事实卡 + 隐藏技能（鉴定 / 盯防） | 发言、标记、质询、投票 |
| 来电骗子（1 人） | 谎言剧本卡 + 烟雾弹 | 同上；目标是误导投票 |
| 系统主持 | 全量剧本与身份 | 播报摘要、点名、结算与价值复盘 |

身份卡与技能鉴定结果**仅私发本人**；骗子 `player_id` 只存服务端，结算前不进入公开主持词。

### 对局流程（状态机）

```text
大厅 lobby
  → 来电播报 briefing          （混真假摘要；发放隐藏技能）
  → 盘问 statement             （轮流发言）
  → 物证播报 evidence          （公开线索板，可鉴定 / 放烟雾）
  → 怀疑标记 mark              （点名可疑者；决定质询热度）
  → 交叉质询 cross_exam        （按热度追问 2～3 人）
  → 投票 vote
  → 结算 end                   （胜负 + 个人评分 + 反诈价值复盘）
```

| 阶段 | 玩家体验 | 系统行为 |
| --- | --- | --- |
| 大厅 | 选剧本、组队，可补机器人 | 人数校验（≥3，≤6） |
| 来电播报 | 听可疑来电摘要 | TTS 播报；不下发身份真伪 |
| 盘问 | 说明「信哪句、疑谁」 | 记录发言，推进发言权 |
| 物证 | 研判线索板真假 | 公开部分线索；处理技能 |
| 标记 | 点名最可疑者 | 汇总怀疑热度 |
| 质询 | 被点名短答 | 按热度 + 盯防加权选题 |
| 投票 | 指认骗子 | 多数决；输出评分与价值复盘 |

**胜负**：命中骗子 → 市民胜；否则 → 骗子胜。

### 隐藏技能

| 技能 | 阵营 | 效果 |
| --- | --- | --- |
| 物证鉴定 | 市民 | 私密得知一条物证真伪 |
| 重点盯防 | 市民 | 指定一人必进质询名单 |
| 烟雾弹 | 骗子 | 物证阶段混入一条误导假线索 |

### 内容模型与剧本库

单局剧本 `CallScript`：公开 `Briefing`、私密身份卡 / 角色本、质询题库、机器人台词、物证真伪表、结算价值点。  
**同一状态机，只换剧本包**——便于机构定制与内容授权。

| ID | 标题 | 题材 |
| --- | --- | --- |
| `midnight-bank` | 午夜银行来电 | 伪冒银行风控 / 安全账户 |
| `black-gold-antifraud` | 黑金公司反诈侦查 | 话术组伪装受害者（角色本） |
| `refund-courier` | 快递清关退款来电 | 虚假清关费 / 退款短链 |
| `pig-butcher-love` | 网恋理财杀猪盘 | 交友诱导虚假投资 |
| `ai-voice-kin` | AI 换声亲友急电 | AI 克隆声音催转保证金 |
| `campus-parttime` | 校园兼职刷单局 | 垫付刷单 / 发展下线 |

### 体验原则与成功指标

- 节奏可控：每阶段有主持引导；播报 / 物证可由玩家确认推进，避免打断朗读  
- 降级友好：单人补机器人即可完整跑通，利于展台 Demo  
- 教育不说教：结算用「哪句是假的、正规机构不会怎样」轻量复盘  

| 类型 | 建议指标 |
| --- | --- |
| 体验 | 完整对局完成率、平均时长、复玩率 |
| 教育 | 关键话术识别正确率（可选短问卷） |
| 商业 | 定制转化、活动场次、剧本授权数 |
| 平台 | 会话时长、ASR/TTS 调用量、Demo 转化 |

## 架构设计

### 总体原则

> **灵矽做语音通道与智能体编排，本服务做对局权威状态。**

通道与规则解耦：灵矽可独立升级 ASR/TTS/Agent；对局引擎可独立扩剧本、技能与评分，双方仅通过 **MCP 工具契约**协作。

### 逻辑架构

```text
┌──────────────────────────────────────────────────────────────┐
│                    接入层（灵矽 / Web Demo）                    │
│         智能硬件 · Realtime/WebRTC 客户端 · 浏览器演示页         │
└────────────────────────────┬─────────────────────────────────┘
                             │ 音频 / 文本
┌────────────────────────────▼─────────────────────────────────┐
│                      灵矽 linxdv0                               │
│              ASR → 主 Agent（意图 / FC）→ TTS                   │
│           （可选：声纹映射 player_id、多音色主持）                │
└────────────────────────────┬─────────────────────────────────┘
                             │ MCP / HTTP
┌────────────────────────────▼─────────────────────────────────┐
│                   《来电疑云》对局服务（本仓库）                  │
│  mcp 工具面 · room 多房间 · game 状态机/剧本/技能 · api/WS Demo │
│  tts CosyVoice 代理（Demo 与灵矽音色对齐）                      │
└──────────────────────────────────────────────────────────────┘
```

### 生产对接链路

```text
玩家语音
  → 灵矽设备 / Realtime 客户端
  → linxdv0（ASR → 主 Agent → TTS）
  → Function Call / 自定义 MCP
  → 本服务 POST /mcp/call
  → internal/game 状态机更新
  → get_state.hostLine 回传
  → 灵矽 TTS 播报至各玩家会话
```

当前 Web Demo 用「浏览器 / CosyVoice TTS + 本地 Whisper」模拟通道，**状态机与工具语义与生产一致**，仅传输层不同。

### 模块职责

| 模块 | 路径 | 职责 |
| --- | --- | --- |
| 入口 | `cmd/server` | 进程启动、路由挂载 |
| 对局引擎 | `internal/game` | 阶段迁移、身份/技能、发言/物证/标记/质询/投票、评分与价值复盘 |
| 房间管理 | `internal/room` | 多房间 Hub、机器人补齐与自动推进 |
| MCP 工具面 | `internal/mcp` | 向灵矽暴露稳定工具契约 |
| HTTP / WS | `internal/api` | Web 演示同步；可被中间层转发 |
| CosyVoice TTS | `internal/tts` | Demo 多音色；需 `DASHSCOPE_API_KEY` |
| 本地 ASR | `scripts/asr_transcribe.py` | Demo 按住说话；生产替换为灵矽 ASR |
| Web 客户端 | `web/` | 无设备时的完整可玩演示 |

### MCP 工具契约

| 接口 | 说明 |
| --- | --- |
| `GET /mcp/tools` | 工具列表 |
| `POST /mcp/call` | `{"name":"start_game","arguments":{"room_code":"ABCD"}}` |
| `GET /mcp/` | 简易 SSE endpoint 提示 |

| 工具 | 语义 |
| --- | --- |
| `create_room` / `join_room` / `fill_bots` | 建房、入房、补机器人 |
| `start_game` | 开局，分配身份与技能 |
| `advance_phase` | 播报→盘问，或物证→怀疑标记 |
| `submit_statement` / `submit_cross_answer` | 盘问 / 质询发言 |
| `mark_suspect` | 怀疑标记 |
| `use_ability` | 发动隐藏技能 |
| `vote` | 投票指认 |
| `get_state` | 公开状态 + `hostLine`（可附私密卡） |

### 安全与一致性边界

| 数据 | 可见性 |
| --- | --- |
| `PublicState` | 全员：阶段、玩家、发言、物证板、标记进度、评分、主持词 |
| `PrivateView` | 仅本人：角色、身份卡、技能、鉴定结果 |
| 骗子身份 | 仅服务端；结算前不写入公开 `hostLine` |

实现要点：阶段门禁、发言权校验、标记/投票幂等、房间容量 3–6 人保证语音轮次可控。

### 与灵矽能力映射

| 灵矽能力 | 用途 | 优先级 |
| --- | --- | --- |
| 设备 WebSocket / Realtime | 玩家进房说话 | P0 |
| 流式 ASR / TTS | 发言入库、播报 `hostLine` | P0 |
| 主 Agent + Function Call / 自定义 MCP | 意图识别并调本服务工具 | P0 |
| APP State + 动态工具 | 按阶段禁用工具，减少误调 | P1 |
| 声纹 V2 | 同设备多人映射 `player_id` | P2 |
| 多音色 / 音色复刻 | 主持与角色分音色增强沉浸 | P2 |

> 灵矽 `app/meeting` 是会议纪要场景，**不是**本游戏的多人房间底座；房间状态由本服务维护。

### 部署与演进

```text
[灵矽控制台] 智能体 → 绑定自定义 MCP URL
        │
        ▼
[本服务] Demo 单实例即可；生产可按房间分片
        ├── 状态：内存（MVP）→ Redis / 持久化（机构多场次）
        ├── 剧本：内置包 → CMS / 配置中心
        └── 观测：完成率、工具延迟、ASR/TTS 失败率
```

| 阶段 | 目标 | 关键交付 |
| --- | --- | --- |
| **MVP（当前）** | 可玩、可演示、可对接 | Web Demo + 状态机（含物证/技能）+ MCP + 六部剧本 + CosyVoice |
| **接入版** | 真机全语音闭环 | 灵矽 MCP 正式配置、设备 ASR/TTS、意图话术调优 |
| **内容版** | 可售剧本包 | 剧本 CMS、行业模板、结算词库 |
| **机构版** | 可签单 | 组织账号、场次、正确率报告、Branding |
| **平台版** | 可规模化 | 匹配大厅、排行榜、作者投稿、声纹同设备 |

## 商业价值

### 问题与机会

市面反诈内容多为**单向宣教**（短视频、海报、答题），留存差、效果难量化；狼人杀类产品多为**纯娱乐社交**，缺少可对外交付的行业内容。二者之间存在空白：

| 痛点 | 机会 |
| --- | --- |
| 宣教触达难、记不住 | 用「完整对局」替代「听讲座」，天然具备复玩与口碑传播 |
| 机构有培训预算，缺沉浸式交付物 | 剧本可按行业定制，对局过程可沉淀为参与与表现数据 |
| 语音硬件 / Agent 平台需要垂直内容包 | 《来电疑云》可作为标杆语音应用，拉动设备与平台曝光 |

### 价值主张

```text
多人语音博弈（粘性）
    → 灵矽通道（送达客厅 / 展台 / 培训室）
    → AI 主持与角色（降低组织成本）
    → 反诈剧本包（机构买单理由与社会价值）
```

### 目标客群

**一期（高意愿场景）**

| 客群 | 典型场景 | 核心诉求 |
| --- | --- | --- |
| 银行 / 支付机构 | 反诈主题月、网点体验区 | 品牌露出 + 用户风险意识 |
| 社区 / 学校 | 安全教育课、社区日 | 低门槛、可组织、有教育意义 |
| 企业 HR / 安全培训 | 防社工、防钓鱼演练 | 可复用剧本 + 出勤与表现数据 |
| 运营商 / 保险 | 公益活动、客户日 | 公益叙事 + 互动引流 |
| 灵矽设备渠道 | 展会 Demo、开箱内容 | 展示 ASR / TTS / Agent 全链路 |

**二期**：家庭轻社交、行业剧本投稿、平台内容包分成。

### 商业模式

| 模式 | 说明 | 收入形态 |
| --- | --- | --- |
| 机构定制 | 按品牌话术与合规口径定制剧本 / 结算文案 | 项目制 |
| 内容授权 | 剧本包授权给培训机构、设备商、活动公司 | 授权费 / 年费 |
| 线下互动 | 「语音对局台」进驻展会、网点、校园 | 活动服务 + 设备租赁 |
| 培训数据后台 | 组织开局、名单、投票准确率、薄弱话术标签 | SaaS / 按场次 |
| 平台内容包（远期） | 灵矽应用市场上架，按设备侧分成 | 分成 / 订阅 |

### 路演一句话

> 《来电疑云》把狼人杀式的语音博弈，装进真实诈骗话术里：玩家听得懂、说得清、投得准——机构拿到的是可演示、可定制、可复盘的反诈互动产品，平台拿到的是可运营的语音内容样板。

## 总结

《来电疑云》用**狼人杀式语音博弈**解决反诈内容「听不进、记不住」的问题，用**灵矽语音通道**解决「怎么送到用户嘴边」的问题，用**服务端权威状态机 + MCP 工具面**解决「游戏规则如何与智能体可靠协作」的问题。

- **产品上**：阶段清晰、语音优先、技能与物证加深博弈、剧本可换  
- **架构上**：通道与对局解耦；Web Demo 已验证同一套语义，可平滑升级至灵矽生产链路  
- **商业上**：面向银行、社区、企业培训与线下活动，走定制与授权
