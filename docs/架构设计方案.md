## 1. 设计目标与原则

### 1.1 核心原则

> **灵矽做语音通道与智能体编排，本服务做对局权威状态。**

| 原则 | 说明 |
| --- | --- |
| 通道与规则解耦 | ASR/TTS/Agent 可替换；阶段/身份/胜负不交给模型自由发挥 |
| 单一真相源 | 房间状态仅存在于 `internal/game.Room`（经 `room.Hub` 管理） |
| 契约稳定 | 对外以 MCP 工具面为稳定 API；Web 与灵矽共用同一语义 |
| 信息分层 | `PublicState` / `PrivateView` / 服务端机密严格隔离 |
| Demo ≈ 生产语义 | Web Demo 仅替换传输层，不另起一套规则 |

### 1.2 质量属性优先级

| 属性 | 优先级 | 策略 |
| --- | --- | --- |
| 正确性（规则公平） | P0 | 阶段门禁、发言权、投票幂等 |
| 可演示性 | P0 | 单实例内存态 + 机器人 + Web |
| 可对接性 | P0 | MCP JSON 工具契约 |
| 可扩展性（剧本） | P1 | `CallScript` 注册表 |
| 可扩展性（规模） | P2 | 房间分片 / 状态外置（演进） |
| 可观测性 | P2 | 完成率、工具延迟、TTS/ASR 失败率 |

## 2. 系统上下文

```text
                 ┌─────────────────────┐
   玩家语音/点击  │  接入端               │
 ───────────────►│  灵矽设备 / Realtime  │
                 │  / Web 浏览器         │
                 └──────────┬──────────┘
                            │ 音频或已转写文本
                 ┌──────────▼──────────┐
                 │  灵矽 linxdv0         │
                 │  ASR → Agent → TTS   │
                 └──────────┬──────────┘
                            │ MCP HTTP
                 ┌──────────▼──────────┐
                 │  来电疑云对局服务       │
                 │  （本仓库 Go 服务）     │
                 └─────────────────────┘
```

**责任边界：**

| 系统 | 负责 | 不负责 |
| --- | --- | --- |
| 灵矽 | 设备接入、ASR、意图识别、TTS 播报、会话保活 | 判定谁是骗子、推进胜负 |
| 本服务 | 房间、阶段、身份、技能、计票、主持词、评分 | 声学前端、模型推理 |
| Web Demo | 在无设备时模拟「人机语音环」 | 生产级鉴权与多租户 |

> 注意：灵矽仓库中的 `app/meeting`（会议纪要）不是本游戏的多人房间底座。

## 3. 逻辑架构

```text
┌──────────────────────────────────────────────────────────────┐
│                         接入层                                │
│   ESP32 / 小智协议 · OpenAI Realtime · web/ 静态页             │
└────────────────────────────┬─────────────────────────────────┘
                             │
┌────────────────────────────▼─────────────────────────────────┐
│                      编排层（灵矽）                             │
│   流式 ASR · 主 Agent / Function Call · 流式 TTS · 可选声纹    │
└────────────────────────────┬─────────────────────────────────┘
                             │ POST /mcp/call · GET /mcp/tools
┌────────────────────────────▼─────────────────────────────────┐
│                    对局服务（本仓库）                            │
│  ┌─────────┐  ┌─────────┐  ┌──────────────┐  ┌────────────┐ │
│  │ mcp     │→ │ room    │→ │ game         │  │ tts        │ │
│  │ 工具面   │  │ Hub     │  │ 状态机/剧本   │  │ CosyVoice  │ │
│  └─────────┘  └─────────┘  └──────────────┘  └────────────┘ │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │ api：HTTP REST + WebSocket 推送 + ASR 上传入口            │ │
│  └─────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 模块职责

| 模块 | 路径 | 职责 | 关键类型 |
| --- | --- | --- | --- |
| 入口 | `cmd/server` | 监听端口、挂载路由、静态资源 | — |
| 对局引擎 | `internal/game` | 阶段迁移、身份/技能、发言/物证/标记/质询/投票、评分、价值复盘、机器人策略 | `Room`, `CallScript`, `PublicState`, `PrivateView` |
| 房间管理 | `internal/room` | 多房间实例、创建/查找、定时驱动机器人 | `Hub` |
| MCP | `internal/mcp` | 工具列表与调用分发 | `Server.Call` |
| HTTP/WS | `internal/api` | REST、WebSocket 订阅、ASR、TTS 代理入口 | — |
| TTS | `internal/tts` | 百炼 CosyVoice 多音色、缓存 | `voices.go` |
| Web | `web/` | 演示客户端：状态渲染、TTS 队列、录音 | — |
| 脚本 | `scripts/` | Whisper 转写、无头 demo | — |

### 3.2 依赖方向

```text
cmd/server
  → api, mcp, room, tts
api / mcp
  → room → game
tts
  →（外部）DashScope CosyVoice
web
  → api（HTTP/WS）/ tts（音频）
```

禁止：`game` 依赖 `api`/`mcp`；规则层保持纯领域逻辑，便于单测。

## 4. 对局状态机

### 4.1 阶段枚举

| Phase | 值 | 说明 |
| --- | --- | --- |
| Lobby | `lobby` | 组队 |
| Briefing | `briefing` | 来电播报 |
| Statement | `statement` | 盘问发言 |
| Evidence | `evidence` | 物证播报 |
| Mark | `mark` | 怀疑标记 |
| CrossExam | `cross_exam` | 交叉质询 |
| Vote | `vote` | 投票 |
| Reveal | `reveal` | 揭晓（内部瞬态） |
| End | `end` | 结算 |

### 4.2 迁移图

```text
lobby --Start--> briefing
briefing --AdvanceFromBriefing--> statement
statement --全员发言--> evidence
evidence --AdvanceFromEvidence--> mark
mark --全员标记--> cross_exam
cross_exam --全员回答--> vote
vote --全员投票--> reveal --> end
```

非法迁移返回 `ErrWrongPhase`。

### 4.3 关键命令与前置条件

| 命令 | 合法阶段 | 校验 |
| --- | --- | --- |
| `Start` | lobby | 人数 ≥ MinPlayers |
| `AdvanceFromBriefing` | briefing | — |
| `SubmitStatement` | statement | 必须为当前发言者 |
| `AdvanceFromEvidence` | evidence | — |
| `MarkSuspect` | mark | 目标存活、非自己、未重复标记 |
| `UseAbility` | 按技能限制 | 未使用过；audit 需有效 clueId；focus 需有效目标；smoke 仅 evidence |
| `SubmitCrossAnswer` | cross_exam | 必须为当前被质询者 |
| `CastVote` | vote | 目标合法、未重复投票 |

### 4.4 主持词 `hostLine`

- 每次阶段变化或关键事件后更新  
- 作为 TTS / Agent 播报的**唯一公开文案入口**  
- 禁止写入骗子身份等机密  

### 4.5 机器人自动推进

`Room.AutoActBots` 由 Hub 定时触发：

| 阶段 | 机器人行为 |
| --- | --- |
| briefing / evidence（推进） | **不**自动 advance（避免打断真人听播报） |
| evidence | 骗子 bot 可放烟雾弹 |
| statement / cross | 到自己则提交台词库文本 |
| mark | 可盯防 + 标记 |
| vote | 按简单策略投票 |

`nextBotActAt` 做节流，避免刷屏。

## 5. 数据模型

### 5.1 公开 / 私密 / 机密

| 视图 | 内容 | 下发方式 |
| --- | --- | --- |
| `PublicState` | 阶段、玩家列表、发言、物证板、标记进度、质询、投票进度、评分、价值复盘、`hostLine` | REST / WS / `get_state` |
| `PrivateView` | role、身份卡、角色名、技能、技能提示、鉴定结果 | 按 `player_id` 私发 |
| 服务端机密 | 骗子 ID、`EvidenceClue.IsTrue`、未揭示 planted 语义 | 永不下发 |

### 5.2 剧本 `CallScript`

注册表：`scriptOrder` + `scriptRegistry`（见 `script.go` / `script_extra.go` / `script_blackgold.go`）。

扩展新剧本步骤：

1. 实现 `scriptXxx() CallScript`  
2. 增加常量 ID  
3. 写入 `scriptOrder` 与 `scriptRegistry`  
4. 补齐 `EvidenceClues` 与 `ValuePoints`  

无需改状态机。

### 5.3 房间内运行时字段（概念）

```text
Room
  ├── Script, Phase, Players, order
  ├── statements, crossQuestions, votes
  ├── evidenceClues, publicClues, marks, focusTargetID, smokeUsed
  ├── scores, valueTheme/Points/Closing/Summary
  ├── hostLine, phaseDeadline, nextBotActAt
  └── mu（并发锁）
```

| GET | `/mcp/tools` | 工具 schema 列表 |

| GET | `/mcp/` | SSE endpoint 提示（兼容探测） |

| 工具名 | 作用 |
| --- | --- |
| `create_room` | 建房，可选 `script_id` |

| `start_game` | 开局 |
| `advance_phase` | briefing→statement 或 evidence→mark |
| `submit_statement` | 盘问发言 |
| `mark_suspect` | 怀疑标记 |
| `use_ability` | 技能；可返回 private |

| `vote` | 投票；支持 `target_name` |
| `get_state` | 公开状态；可选附带 private |

### 6.2 HTTP API（Web Demo）

典型资源（以实现为准）：

| 方法 | 路径 | 说明 |

| POST | `/api/rooms` | 创建房间 |
| POST | `/api/rooms/{code}/join` | 加入 |
| POST | `/api/rooms/{code}/fill-bots` | 补机器人 |
| POST | `/api/rooms/{code}/start` | 开始 |
| POST | `/api/rooms/{code}/advance` | 推进 briefing/evidence |
| POST | `/api/rooms/{code}/statement` | 发言 |
| POST | `/api/rooms/{code}/mark` | 标记 |
| POST | `/api/rooms/{code}/ability` | 技能 |
| POST | `/api/rooms/{code}/cross` | 质询回答 |

### 6.3 WebSocket 推送

- 服务端在状态变更后 `broadcastRoom`  
- 每条消息可附带该连接玩家的 `private`  
- 客户端以最新 `PublicState` 全量渲染（MVP 不做增量 patch）

## 7. 语音与音色子系统

### 7.1 Demo 链路

```text
主持/玩家文本
  → web TTS 队列
  → 有 DASHSCOPE_API_KEY？
        ├─ 是 → POST /api/tts → CosyVoice → 播放音频
        └─ 否 → speechSynthesis
玩家语音
  → MediaRecorder
  → /api/asr → scripts/asr_transcribe.py（Whisper）
  → 填入发言框 / 提交
```

### 7.2 音色映射（与灵矽种子对齐）

| 用途 | CosyVoice voice | 产品名（示意） |
| --- | --- | --- |
| 主持 | `longxian_v2` | 豪放可爱女 |
| 玩家轮换 | `longze_v2` / `kabuleshen_v2` / `longcheng_v2` | 温暖元气男 / 实力歌手男 / 智慧青年男 |

实现注意：玩家句超时宜宽松（避免误降级为浏览器音）；主持快读可短超时。

### 7.3 生产替换点

| Demo 组件 | 生产替换 |
| --- | --- |
| Whisper 脚本 | 灵矽流式 ASR |
| `/api/tts` 或浏览器 TTS | 灵矽流式 TTS |
| Web 按钮意图 | Agent Function Call |

**状态机与 MCP 工具名保持不变。**

## 8. 安全、一致性与并发

### 8.1 并发

- `Room.mu` 保护单房间状态  
- Hub 管理房间 map；读多写少场景下 MVP 足够  
- WS 写泵与广播需避免死锁（先快照再发送）  

### 8.2 一致性规则

| 规则 | 实现要点 |
| --- | --- |
| 阶段门禁 | 各命令检查 `Phase` |
| 发言权 | `order[speakerIdx]` / `crossIdx` |
| 幂等 | marks/votes map 防重复 |
| 容量 | MinPlayers / MaxPlayers |
| 机密隔离 | Snapshot 不读 Role 到公开玩家列表 |

### 8.3 威胁与缓解（MVP）

| 威胁 | 缓解 |
| --- | --- |
| 伪造 playerId 读私密卡 | Demo 信任查询参数；机构版需会话令牌 |
| 刷工具调用 | 生产加房间级限流 |
| TTS 密钥泄露 | 仅服务端持有 `DASHSCOPE_API_KEY` |
| 剧本剧透进公开 API | `ScriptMetas` 不含身份卡 |

## 13. 决策记录（ADR 摘要）

| 决策 | 选项 | 结论 | 理由 |
| --- | --- | --- | --- |
| 规则权威方 | Agent 内推理 vs 服务端状态机 | 服务端状态机 | 可测、可公平、防幻觉改规则 |
| 对接协议 | 纯私有 REST vs MCP 工具 | MCP + REST 并存 | 灵矽原生友好；Web 仍用 REST/WS |
| 播报推进 | 纯超时自动 vs 显式 advance | 显式 advance（briefing/evidence） | 避免打断朗读 |
| 内容扩展 | 改代码分支 vs 剧本包 | 剧本注册表 | 同引擎多题材 |
| Demo 音色 | 仅浏览器 vs CosyVoice | CosyVoice 优先 + 回退 | 与灵矽展台体验一致 |

---

## 14. 总结

本架构把《来电疑云》拆成清晰两层：**灵矽负责听与说，本服务负责裁与判**。以 MCP 工具契约为稳定边界，以 `Room` 状态机为单一真相源，以剧本包与技能子系统承载产品深度。Web Demo 验证语义，生产仅替换语音通道，即可平滑进入真机与机构交付。
