## 1. 产品定位

### 1.1 一句话

《来电疑云》是一款运行在灵矽语音智能体之上的**多人语音辨谎游戏**：系统播报一通混有真假信息的「可疑来电」，玩家通过轮流盘问、物证研判、怀疑标记、交叉质询与集体投票，找出隐藏在队伍中的「来电骗子」，并在沉浸式对局中提升真实场景下的风险判断力。

### 1.2 定位三角

```text
          语音博弈（好玩）
               /\
              /  \
             /    \
   灵矽通道 -------- 反诈剧本
   （可送达）        （有价值）
```

- **玩法层**：狼人杀式信息不对称与发言博弈 → 保证「想再来一局」  
- **内容层**：真实诈骗话术剧本 → 保证「玩完记得住」  
- **通道层**：灵矽设备 / Realtime / Web Demo → 保证「能进客厅、展台、培训室」  

口号：**好玩是入口，防骗是结果。**

### 1.3 与赛题约束对齐

| 赛题约束 | 产品落点 | 刻意不做 |
| --- | --- | --- |
| 语音类游戏 | 主持 TTS + 玩家口头发言为主链路 | 不以图文 UI 为唯一交互 |
| 不能是跑团 | 无 DM、无自由叙事推进；胜负由状态机裁定 | 不做开放世界剧情分支 |
| 如狼人杀 | 隐藏身份 + 发言 + 投票出局 | 不做夜间刀人等复杂阵营战 |

### 1.4 目标用户

| 分层 | 用户 | 场景 | 成功标准 |
| --- | --- | --- | --- |
| 核心 Demo | 评委 / 展台观众 | 3–6 分钟可感知完整闭环 | 单人补机器人能跑通一局 |
| 活动组织者 | 银行网点、社区、校园 | 反诈主题日、安全教育课 | 低组织成本、有教育收束 |
| 玩家 | 朋友局 / 家庭局 | 客厅语音娱乐 | 听得懂、说得清、投得出 |
| 平台方 | 灵矽渠道 | 展示 ASR/TTS/Agent | 全链路可演示 |

## 2. 设计原则

| 原则 | 含义 | 产品体现 |
| --- | --- | --- |
| 可听懂 | 闭眼能跟局 | 全程 `hostLine` 驱动节奏 |
| 可说清 | 适配 ASR 与设备麦 | 短口语发言；打字降级 |
| 可裁定 | 规则公平、可复现 | 服务端权威状态机 |
| 可扩展 | 内容与通道解耦 | 换剧本不改引擎；换灵矽不改规则 |
| 降级友好 | 无设备也能演示 | Web Demo + 机器人补齐 |
| 教育不说教 | 收束有价值但不打断乐趣 | 结算短复盘 + 个人评分 |

## 3. 核心玩法

### 3.1 一句话规则

房间内混入 **1 名来电骗子**；其余为市民。听完可疑来电后，通过发言与物证博弈，投票指认骗子：命中则市民胜，否则骗子胜。

### 3.2 角色设计

| 角色 | 人数 | 目标 | 私密信息 | 公开行为 |
| --- | --- | --- | --- | --- |
| 市民（Citizen） | N−1 | 找出骗子 | 可靠事实卡 + 技能（鉴定/盯防） | 发言、标记、质询、投票 |
| 来电骗子（Scammer） | 1 | 误导投票、存活至错投 | 谎言剧本卡 + 烟雾弹 | 同上（伪装成市民） |
| 系统主持 | 1 | 控场与结算 | 全量剧本与身份 | 播报、点名、揭晓、价值复盘 |

**信息安全硬约束：**

- 身份卡、技能鉴定结果仅私发本人（`PrivateView`）  
- 骗子 `player_id` 仅存服务端，结算前不得进入公开 `hostLine`  
- 物证真伪字段 `IsTrue` 仅服务端持有；公开物证板不带真伪标签  

### 3.3 隐藏技能

技能在开局发放，每人一局一次（除非规则另有说明）。

| 技能 ID | 名称 | 阵营 | 可用阶段 | 效果 | 设计意图 |
| --- | --- | --- | --- | --- | --- |
| `audit` | 物证鉴定 | 市民 | 物证 / 标记 | 私密得知一条物证真伪 | 给认真研判的玩家信息优势 |
| `focus` | 重点盯防 | 市民 | 标记（亦可物证） | 指定一人必进质询名单 | 把怀疑转化为机制结果 |
| `smoke` | 烟雾弹 | 骗子 | 物证 | 向物证板植入一条假线索 | 让骗子有主动搅局手段 |

技能提示出现在私密身份卡下方；鉴定结果追加到私密视图，不广播全文。

### 3.4 对局阶段（玩家视角）

```text
大厅 → 来电播报 → 盘问 → 物证播报 → 怀疑标记 → 交叉质询 → 投票 → 结算
```

| 阶段 | 时长感（建议） | 玩家做什么 | 主持做什么 | 阶段出口 |
| --- | --- | --- | --- | --- |
| **大厅 lobby** | — | 选剧本、建房/加入、可补机器人 | 欢迎与规则提示 | 满 3 人且有人点开始 |
| **来电播报 briefing** | 30–90s | 听摘要；查看私密身份与技能 | TTS 播报 `Briefing` | 玩家确认「进入盘问」（不自动跳，避免打断朗读） |
| **盘问 statement** | 每人 20–45s | 轮流说明信哪句、疑谁 | 点名下一位；记录发言 | 全员发言完毕 → 物证 |
| **物证 evidence** | 40–60s | 看线索板；可用鉴定/烟雾弹 | 播报物证摘要 | 玩家确认「进入怀疑标记」 |
| **怀疑标记 mark** | 20–40s | 每人点名最可疑者；可用盯防 | 统计标记进度 | 全员标记完毕 → 质询 |
| **交叉质询 cross_exam** | 每题 20–40s | 被点名者短答 | 按怀疑热度 + 盯防选 2～3 人追问 | 全部回答完毕 → 投票 |
| **投票 vote** | 20–40s | 指认骗子（不可投自己） | 催票、统计 | 全员投票 → 揭晓结算 |
| **结算 end** | 30–60s | 听胜负、看评分与价值复盘 | 公布骗子、教育向收束 | 可再开一局 |

**胜负判定：**

- 得票最高者唯一且为其骗子 → **市民胜**  
- 平票或最高票不是骗子 → **骗子胜**  

### 3.5 物证板与怀疑热度

**物证板：**

- 来源：剧本 `EvidenceClues`（真假混杂，公开时去掉真伪）  
- 公开数量：通常抽取 3 条左右（实现以引擎为准）  
- 骗子烟雾弹可追加「临时补充」假线索，标记为 planted，结算前不对玩家揭示「这是假的」  

**怀疑标记 → 质询名单：**

- 每人一票标记（不可标自己）  
- 被标记次数形成热度榜  
- 质询优先选择热度高者；若有人发动「重点盯防」，该目标强制入选  
- 人数 ≥5 时可质询至 3 人，否则通常 2 人  

### 3.6 结算：评分 + 价值复盘

**个人评分（示意维度，以实现为准）：**

| 维度 | 市民 | 骗子 |
| --- | --- | --- |
| 投票命中 | +分 | — |
| 标记命中 | +分 | — |
| 技能使用 | 小幅加分 | 使用烟雾弹小幅加分 |
| 阵营胜负 | 胜利加成 | 胜利加成 |

输出：姓名、分数、简短评语；用于局内成就感与机构培训的「表现快照」。

**价值复盘：**

- `Theme`：如「银行反诈宣传 · 安全教育」  
- `ValuePoints`：3–5 条可带走的防范点  
- `Closing`：收束寄语  
- 拼装为可朗读的 `ValueSummary`，Web / 灵矽 TTS 均可播报  

原则：收束要短、要具体、要可执行（「不转安全账户」「挂断回拨」），避免长篇宣讲。

## 4. 交互设计

### 4.1 语音优先意图表

| 玩家意图 | 示例话术 | 系统动作 | MCP / API |
| --- | --- | --- | --- |
| 开局 | 「开始游戏」 | 分配身份与技能，进入播报 | `start_game` |
| 结束播报 | 「听完了」「进入盘问」 | briefing → statement | `advance_phase` |
| 盘问发言 | 「安全账户最假……」 | 记录发言 | `submit_statement` |
| 结束物证 | 「进入标记」 | evidence → mark | `advance_phase` |
| 怀疑标记 | 「我怀疑张三」 | 写入标记 | `mark_suspect` |
| 发动技能 | 「鉴定第二条」「盯防李四」 | 处理技能 | `use_ability` |
| 质询回答 | 「因为正规银行不会……」 | 记录回答 | `submit_cross_answer` |
| 投票 | 「我投王五」 | 计票 | `vote` |
| 查状态 | 「现在什么阶段」 | 播报 `hostLine` | `get_state` |

### 4.2 Web Demo 交互（当前已实现）

| 能力 | 说明 |
| --- | --- |
| 剧本选择 | 大厅卡片选择 `scriptId` |
| 组队 | 创建 / 加入房间；一键补机器人 |
| 播报控制 | 「听完了」/「跳过朗读」推进阶段；主持 TTS 可跳过 |
| 发言 | 打字 + 按住说话（本地 Whisper）+ 点按录音 |
| 物证 / 技能 | 物证板展示；鉴定 / 烟雾 / 盯防按钮按阶段出现 |
| 标记 / 投票 | 点选玩家；显示怀疑热度 |
| 多音色 | CosyVoice：主持女声 + 玩家三男声轮换；无密钥回退浏览器 TTS |
| 结算 | 价值复盘卡片 + 评分榜 + 可朗读复盘 |

### 4.3 正式环境（灵矽）交互差异

语义不变，通道升级：

- ASR：设备 / Realtime 流式识别 → Agent 抽槽 → MCP  
- TTS：设备侧播报 `hostLine`（可多音色）  
- 意图：主 Agent Function Call；可用 APP State 按阶段禁用工具

## 5. 内容体系

### 5.1 剧本模型（产品字段）

| 字段 | 对玩家的意义 |
| --- | --- |
| Title / Synopsis | 选关认知 |
| CallerHint | 来电界面氛围 |
| Briefing | 公开听的「可疑来电」 |
| CitizenCard / ScammerCard 或 Characters | 私密身份与立场 |
| CrossQuestions | 质询题库 |
| EvidenceClues | 物证真伪表（公开时去真伪） |
| BotStatements / BotCrossAnswers | 机器人按阵营发言 |
| Theme / ValuePoints / Closing | 结算教育收束 |

### 5.2 内置剧本矩阵

| ID | 标题 | 题材 | 教育重点 |
| --- | --- | --- | --- |
| `midnight-bank` | 午夜银行来电 | 伪冒银行风控 | 安全账户、验证码、催促话术 |
| `black-gold-antifraud` | 黑金公司反诈侦查 | 话术组伪装受害者 | 公检法、刷单、跑分、虚假理财 |
| `refund-courier` | 快递清关退款来电 | 虚假清关 / 退款短链 | 官方查单、付小退大陷阱 |
| `pig-butcher-love` | 网恋理财杀猪盘 | 交友诱导投资 | 小赚诱饵、解冻税、托儿 |
| `ai-voice-kin` | AI 换声亲友急电 | AI 克隆声音 | 挂断回拨、禁止隔绝核实 |
| `campus-parttime` | 校园兼职刷单局 | 垫付刷单 | 违规刷单、再下一单解冻 |

扩展路径建议：冒充公检法专章、虚假征信修复、养老理财专场、行业定制（银行自家话术库）。

### 5.3 内容生产规范（给编剧）

1. Briefing 必须**真假混杂**，且假点对应现实高发话术  
2. 市民卡只给「可靠事实」，不给「谁是骗子」  
3. 骗子卡给出可执行的圆谎策略，避免无台词可演  
4. 每条 ValuePoint 应可独立印成海报金句  
5. 质询题要短、要逼人表态，适配语音回答

## 6. 体验节奏与边界

### 6.1 人数与时长

| 项 | MVP 设定 | 说明 |
| --- | --- | --- |
| 人数 | 3–6 | 保证语音轮次可控 |
| 完整一局 | 约 8–15 分钟 | 展台可砍机器人节奏 |
| 单人演示 | 1 人 + 机器人补齐 | 必保可演示 |

### 6.2 节奏控制策略

- **播报 / 物证不自动跳转**：避免 TTS 被截断；由玩家或 Agent 调 `advance_phase`  
- **机器人节流**：发言间隔约 2s，给真人思考与朗读时间  
- **跳过主持**：允许跳过当前主持朗读并在合适阶段推进  

### 6.3 无障碍与降级

| 情况 | 降级方案 |
| --- | --- |
| 无麦克风 / ASR 失败 | 打字发言 |
| 无 CosyVoice 密钥 | 浏览器 `speechSynthesis` |
| 人数不足 | `fill_bots` |
| 无灵矽设备 | Web Demo 完整可玩 |

### 6.4 明确不做（本期）

- 开放世界跑团、自由技能树  
- 复杂多骗子 / 多阵营夜间行动  
- 强依赖视觉的推理 UI（可有辅助面板，但不替代语音主链路）  
- 结算长视频宣教

## 9. 附录：用户故事（节选）

1. **作为展台演示员**，我希望一个人点「补机器人」就能完整跑完一局，以便随时给评委演示。  
2. **作为市民玩家**，我希望听到来电后能看到物证板，并用鉴定技能确认一条真伪，以便更有依据地投票。  
3. **作为骗子玩家**，我希望能在物证阶段投放烟雾弹，以便扰乱市民判断。  
4. **作为培训组织者**，我希望局末有简明防范点列表，以便可以投影给现场观众带走。  
5. **作为灵矽接入方**，我希望所有玩家动作都对应稳定 MCP 工具，以便 Agent 只做意图识别不做规则裁判。
